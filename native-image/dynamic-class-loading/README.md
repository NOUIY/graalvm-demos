# Runtime Class Loading in a Native Executable

This example shows how to enable the experimental [Runtime Class Loading](https://github.com/oracle/graal/issues/11327) feature in a [GraalVM Native Image](https://www.graalvm.org/latest/reference-manual/native-image/) executable. It uses a [Micronaut](https://micronaut.io/) application and [Byte Buddy](https://bytebuddy.net/) to prove that the enabled executable can define and load a class after startup.

The classes generated by Byte Buddy do not exist during the Native Image build. After the native executable starts, Byte Buddy defines a new `demo.crema.generated.ConferencePlugin...` class, the runtime loads it dynamically, and the application invokes its `message()` method through a method handle.

## Preparation

1. Install GraalVM 25.1+ and Maven, and make GraalVM your active JDK.

2. Clone this repository and navigate to the example directory:
    ```shell
    git clone https://github.com/graalvm/graalvm-demos.git
    cd graalvm-demos/native-image/dynamic-class-loading
    ```

## Run the Application on the JVM

1. Compile the application and run its JVM tests:
    ```shell
    mvn clean test
    ```

    This command compiles the application and test code, then runs the tests.

2. Run the application on the JVM with the sample conference configuration:

    ```shell
    mvn -q compile exec:java -Dexec.args="plugins/conference.properties"
    ```

    `plugins/conference.properties` is a input file containing a conference name, location, and speaker. The application reads it, Byte Buddy generates a new greeting class at run time, and the output includes that generated class name and greeting.

## Build and Run a Native Executable

1. Build with the `dynamic` profile. It enables `-H:+RuntimeClassLoading`:
    ```shell
    mvn clean -Pdynamic package
    ```
    The profile binds the Native Image build to Maven's `package` phase, so `mvn clean -Pdynamic package` both activates the profile and creates the executable.

2. Run the native executable:
    ```shell
    ./target/micronaut-bytebuddy-dynamic
    ```

    You should see `demo.crema.generated.ConferencePlugin1`, proving that Byte Buddy generated and loaded the class at run time.

## Edit the Plugin and Run Again

1. Edit _plugins/conference.properties_ and change `name`, `location`, or `speaker`.

2. Run the demo again:
    ```shell
    ./target/micronaut-bytebuddy-dynamic
    ```

    Each run reads the updated configuration file, generates and loads the class at run time, and prints the new greeting. Edit the file and rerun the native executable as often as you like—there is no need to rebuild it.

3. Load another plugin file:

    ```shell
    ./target/micronaut-bytebuddy-dynamic plugins/conference.properties
    ```
